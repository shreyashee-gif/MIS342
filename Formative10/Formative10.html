Assignment Overview — LuckyTire

LuckyTire is moving from separate database objects toward a complete application. You will combine interface automation with a small VBA module and practice a critical AI-era skill: code can compile successfully and still implement the wrong business rule.

This is a formative assignment. The goal is to learn by building, testing, and checking the database work. You do not need to submit screenshots, a PDF, or Digital Artifact Notebook evidence.

Exercise 1 — Automate a LuckyTire Task and Debug a VBA Business Rule
  1. Download LuckyTire_Normalized_Formative10.accdb and modLuckyTirePricing_Broken.bas. Save the database as Formative10_LuckyTire.accdb.
  2. Create or identify a form that can act as a simple navigation/menu interface.
  3. Create one macro or command button that opens a useful LuckyTire query, form, or report. Run it several times and verify that it opens the intended object.
  4. Open the Visual Basic Editor and import modLuckyTirePricing_Broken.bas as a standard module.
  5. Compile the VBA project. Notice that code can compile even when its business logic is wrong.
  6. Test CalcDiscountedTotal(100, 2, 0.10). The stated business rule says two $100 items with a 10% discount should total $180.
  7. Read the function yourself and predict the logic error before asking Hermes.
  8. Give the .bas source and the $180 expected result to Hermes. Ask it to explain the defect and propose the smallest correction.
  9. Correct the VBA function in Access. Recompile and rerun the same test. Verify that it now returns $180.
  10. If practical, use the corrected function in a query expression or another controlled test with a second known input.
  11. Save and close the database.
